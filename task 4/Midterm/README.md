# StudyShelf — React Midterm Project

A small responsive React Single Page Application for browsing and adding learning resources. Built for the **Midterm Project — React SPA** assignment.

## Run locally

1. Install Node.js (18+).
2. Open this folder in VS Code.
3. Run `npm install`.
4. Run `npm run dev` and visit the localhost URL.
5. Run `npm run build` to verify a production build.

## Features

- **120 initial records** (12 topics × 10 resource titles) generated by the simulated API on first use.
- Async list fetch and async item details with artificial delay and occasional errors.
- Add a resource via a controlled form. Data persists in your browser's `localStorage`.
- Search title, description, and author; filter by subject and difficulty.
- Sort A–Z, newest, shortest, longest; paginate 8 records per page.
- Loading, error, empty, success, and retry states; a Reload button.
- Responsive UI with reusable components.

## Component tree

`App` → `Header`, `StatCard` ×3, `SearchControls`, `ResourceList` → `ResourceCard`, `Pagination`, `DetailPanel`, `AddResourceForm`.

`App` owns shared state such as the list, selected resource, search, filters, sorting and pagination. `AddResourceForm` owns the controlled form state. Props pass information and callbacks down the component tree.

## How effects work

- The list `useEffect` runs on mount and when the Reload button increments `reload`.
- The details `useEffect` runs when `selectedId` or `detailReload` changes.
- Both effects return cleanup callbacks that set `ignore = true`, stopping old responses from replacing current React state. Fast switching cannot display obsolete details.
- There is no direct DOM manipulation or direct `localStorage` access in components.
- Only `useState` and `useEffect` hooks are used. No third-party fetching library.

## Data source

`src/api/libraryApi.js`: simulated asynchronous API using Promises, `setTimeout`, random delays and random errors. It owns `localStorage` access and supplies exactly 120 initial records. A deployed copy uses browser storage, so each browser starts with its own data.

## Deploy to Vercel

1. Push all project files to a GitHub repository. Do not upload `node_modules` or `dist`.
2. Import the repository at https://vercel.com/new.
3. Framework: Vite. Build command: `npm run build`. Output directory: `dist`.
4. Deploy. Test the public URL, especially Reload, selection, search, pagination and adding a resource.
5. Submit your GitHub repository URL, Vercel URL, and press **turn in** before the deadline.

## Defense checklist

Explain `useState`, `useEffect` dependencies, effect cleanup, stale asynchronous responses, props, controlled inputs, stable keys (`key={item.id}`), derived filtered list, conditional rendering, state reset on form submission, and re-rendering after state updates.
